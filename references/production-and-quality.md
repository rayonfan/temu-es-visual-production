# 图文制作与成品验收

用于逐图制作表、模型调用前交接、局部修复和最终验收。研究证据与西语文案见 [研究与策划标准](research-and-planning.md)。

## 1. 商品身份与制作方式

先为素材编号，并记录可见部位、允许用途和复用限制。商品保留清单要落到具体部位，例如「灰绿色织物、黑色包边、前侧低开口」，不要只写「高级质感」。

| 制作方式 | 适用情形 | 执行与限制 |
|---|---|---|
| 原图编辑/实物合成 | 主图、包装小字、标志或结构需要严格一致 | 优先保留真实商品像素，使用可用工具编辑背景、光影或合成新场景；核对投影、边缘、透视与接触关系。抠图只保护已有可见外观，不能补出背面。 |
| 参考图条件生成 | 需要新动作、自然场景或有依据的新视角 | 显式传入对应商品图和禁改清单。生成后逐张与原始资料对照，不拿上一张生成图当唯一事实来源，避免累积漂移。 |
| 概念/遮挡复原 | 原图无法完整提供外观，或用户明确只探索方向 | 记录哪些部位是 AI 推演，不把它当实物细节、微距、内部结构或功能证明。关键外观缺失时选择已有视角或索取必要素材。 |

处理多件套时先识别每件的实际外观和规格，再按用户实际销售单位拆分。用户要求先提取单品时，按最新确认的各件/尺寸制作独立参考资产，核对可见外观后再用于整套制作，额外参考资产与所需主图/详情图分别计数。例如只确认两尺寸，就提取两张，不因旧模板写“三个”补造第三张；两张参考图也不抵扣既定的七张图文成品。互相遮挡的商品卡无法“无损提取”隐藏部分；尺寸已知也不证明未知内部结构。不能把一次 AI 复原标为已核实 SKU。

独立单品参考应为空窝/无使用者的完整商品，背景简洁，无供货卡的商品表格、价格、NEW 徽标或店铺界面。保留商品本身的小标、包边、低开口及织纹；小标字样模糊时不臆造品牌名。主推色和各尺寸明确标在文件名及记录里，不把其它可选颜色混作该 SKU 的外观依据。

“整套重做”意味着新建本次输出并重新调用模型制作每张成品；可继续使用实物参考、事实记录和有效文案，不将旧成品改名、重新打包或只换标题冒充新图。

## 2. 逐图交接字段

每张独立 Prompt 都需包含本图所需信息及真实参考附件，不依赖“上一张/同上”：

- 编号、用途、1:1 或用户指定比例、最终文件名。
- 买家问题、一个主要利益、支持它的 SKU 事实及来源编号。
- 资产类型：套装识别、自然交互、局部功能、面料特写、家居场景、尺寸规格等。
- 商品露出：整套、单件全貌、局部；使用哪个 SKU，是否保留全部件数，哪些道具不属于商品。
- 销售单位、可选颜色/尺寸及该图是否需要“分别售卖/每单一个”说明。提示词明确排除供货卡上与本次单卖冲突的套装字样和价格，不能只在聊天里解释而让模型继续画成套装。
- 镜头距离、角度、人物/宠物个体与动作；这些选择必须有实际画面任务。
- 版式地图：商品区、标题组、证据/引线、尺寸区、安全边距；说明主体宽度或位置时注明口径，不混用宽度百分比和面积百分比。
- 西语准确原文：标题、必要支撑句、标签、尺寸。没有文字的图明确说明无新增文字，不删除实物已有标志。
- 制作方式、参考图角色、具体保留项、禁止新增项、文字渲染/校验方式。
- 系列共用的色彩、字体气质和光线逻辑；本图独有的构图、背景与证据。

不把内部编号、证据等级、占位符、“主图/详情页”、待核事项等写进可见文案。缺少事实时删掉依赖它的文案，内部说明另存。

## 3. 主图与整套画面的变化

主图先回答“卖什么、到手几件、为什么点进来”。套装件数是识别信息，可与一个主利益并存，不为追求单一卖点隐藏所售内容。商品与证明利益的动作/细节是视觉重心；没有依据时不用价格章、信任徽章、购买按钮或促销制造点击理由。

约 160–240 px 的缩略预览可用于内部识别检查，属于设计检查，不是 Temu 官方尺寸。缩小后若只见标题或装饰、看不清商品和套装内容，先调整商品大小、间距与构图，再加装饰。

统一色板与字体不意味着所有图必须同背景、同角度或同一大标题卡。默认六张详情应覆盖有依据的不同画面任务，例如：

| 任务 | 可选画面与版式 | 不足以完成任务的做法 |
|---|---|---|
| 使用代入 | 中景自然动作，短标题嵌入环境留白 | 同一只狗、同一姿势仅换房间 |
| 围边或开口功能 | 近景枕靠/进入动作，一处短标注 | 再放完整空窝，只写“加高设计” |
| 面料与做工 | 原图可支持的局部特写，织纹/包边对应短说明 | 想象纤维成分或过度平滑真实表面 |
| 搭配/摆放问题 | 有尺度依据的室内摆放、环境关系 | 为换背景新增一张没有信息增量的全景 |
| 选规格或套装内容 | 独立单品、尺寸线、紧邻数字和数量 | 三件嵌套、等大缩略图下堆多组数字 |

不机械套用表中所有模块；缺证据时换成可证实的角度、局部或选购信息，不用虚构剖面、显微图、性能实验填空。

整套制作表至少应体现全貌/场景、局部证据和规格等不同任务（以资料实际支持为准）。相邻图片若商品露出、景别/视角、动作、版式都相同，只换标题或背景，退回重排。不要连续三张重复“完整商品居中 + 顶部大标题”。不同布局服务不同问题，不为变化强行使用无商品文字屏、图标或拆解图。

多张宠物场景按制作表区分个体/犬种、姿势和取景，狗与窝的尺度要可信；不能从未知承重或内径推定适配犬种。用户规定某场景图最多用一次时，逐图记录使用位置；其余场景不继承原狗和原姿势。风格参考不能带入竞品外观、Logo 或功能。

## 4. 西语文字制作

先定稿再生成，不让模型自由补卖点。短标题可原生生成，以保留整体设计感；多规格数字、参数表、长句或字符不稳定时选可控文字层。使用本机实际存在、支持 ñ、á、é、í、ó、ú、ü、¿、¡ 的字体，不强制奢侈品衬线字体或固定字体组合。

原生文字出错时，优先用可用编辑工具局部修字，保留通过检查的商品与版式。需要真实字体兜底时，延续标题组、字重、对齐、色块和间距，不把一段正文随意贴在场景上。工具支持并允许的合成方式才能使用；不假定某脚本、OCR 或软件已安装。

逐字核对标题、支撑句、标签、型号、数字、单位与重音；OCR 可辅助，但不能替代目视和原稿对照。缺字段直接移出成品，不印“待确认”。尺寸文字不能靠近另一规格造成错配。要求带字的图片只有完成图文设计与文字核对才算成品，平台/用户要求无字的槽位除外。

## 5. 验收、修复与交付

按原始资料对照单张大图，再看手机缩略图与整套总览。以下问题分别处理，不能用总分平均掉：

| 检查 | 失败表现 | 修复方向 |
|---|---|---|
| SKU 保真 | 轮廓、开口、包边、织纹、颜色、小标、件数被改 | 回到实物原图编辑/合成或限缩视角，避免继续自由重绘 |
| 图文证据 | 标题讲枕靠却看不到动作；宣称未知防水/机洗 | 改画面或撤掉无证据文案；微距不可冒充检测结果 |
| 套装/尺寸 | 缺件、叠放、同尺寸假装异尺寸、箭头与数字错位 | 依据来源逐项校对每件、相对大小、长宽口径和紧邻标签 |
| 变体/到手数量 | 单卖画成套装，颜色和尺寸选项像全部包含，沿用已纠正的第三尺寸 | 对照用户最新售卖配置，主图改为单件；选择图补清晰的选项及单件说明，删除不存在的规格 |
| 文案与排版 | 西语不通、重音/数字错误、小字不可读、标题压商品 | 减字、重排、局部修字或可控文字层；保留准确商品 |
| 系列差异 | 多图只换背景和标题，宠物/动作重复 | 回制作表改证据层、景别、动作或版式，而非再换颜色 |
| 文件 | 独立图缺失、比例不符、编码或压缩不合要求 | 安全扩图/排版或导出合格副本；未完成如实列明 |

任何商品失真、数量/尺寸错误或无依据主张都不能交付为合格成品。内部“3 秒识别”和设计评分只是审阅工具，不宣称已验证点击率或转化率。

工作资产可使用 `generated-images/<product-slug>/<batch>/`，保留参考图、提示词、方案、总览和 ZIP。整套重做使用新批次，不覆盖旧批次。用户选定父目录下的 SKU 文件夹是另外的成品交付位置，不能用工作目录或模型默认缓存代替。

### 按 SKU 自动保存七张成品

- 调用阶段收集本次 SKU 和存放父目录；“桌面”解析为当前用户的实际桌面，“~”展开为当前用户目录。SKU 与尺寸选项分别记录，不能自动从商品名、供货码或示例造 SKU。只交付文字时无需强制收集这两个字段。
- 七张合格成品产生后，显式列出本批 1 张主图、6 张详情的实际源文件，按顺序交给 [export_sku_images.py](../scripts/export_sku_images.py)，不要通配整个生成目录；否则可能混入单窝参考、旧图或被淘汰版本。使用宿主可用的 Python 3 解释器，示例如下（路径为占位示范，执行时替换）：

```bash
python3 <skill-dir>/scripts/export_sku_images.py --sku "DEMO-PET-BED-GREY" --destination "~/Desktop" --images <主图路径> <详情1路径> <详情2路径> <详情3路径> <详情4路径> <详情5路径> <详情6路径>
```

- 脚本仅复制和校验文件，不生成或编辑图像。默认要求恰好七个不同源文件，新建 `<父目录>/<SKU>/` 并依次命名 `01-main.png`、`02-detail-01.png` 至 `07-detail-06.png`（扩展名按源文件保留）。原始生成文件继续保留。用户明确改变成品张数时使用 `--expected-count`，不得用参考图补足数量。
- 同名文件夹或同名文件已经存在时，不覆盖、不清空，另建 `<SKU>-2`、`<SKU>-3` 等文件夹。SKU 中有 `/`、`\\` 或不能作为目录名的字符时，不静默改变标识；先让用户给出可用的文件夹名。多个 SKU 按明确的图片归属分别归档，不把某个 SKU 的七图套到其他 SKU。
- SKU 成品文件夹只含本次所需的七张图片。单品参考、商品原图、提示词、研究、总览、记录及 ZIP 留在工作目录，若要额外交付给用户，单独给链接。目录不可写、源文件缺失或数量不足时停止完整归档报告，并说明缺项/失败位置。
- 复制后检查数量和源/目标文件哈希一致；截图已生成不等于文件已交付。最终报告 SKU、实际成品文件夹链接和实际张数，不再要求用户自行提取到目录。

每张图记录实际来源、调用提示词、参考附件、工作路径与 SKU 交付路径、实测像素、文件大小和目视核对状态；原始资料在允许的工作目录保留副本。总览可用链接到独立文件的 HTML，不以拼图替代独立详情。完整工作包打包后检查归档可读且齐全，生成图、参考资产和原图分别计数；ZIP 不混入只放七图的 SKU 文件夹。实测像素/大小不沿用历史结果，也不视为平台要求。

只核实实际文件、实际像素与归档完整性，不能替代视觉验收。聊天展示主图与代表性详情预览，提供完整包及目录链接；部分完成时列明完成/缺失编号和原因。不默认创建飞书文档、不要求更换应用；用户另有交付指令时按其执行。
