# 使用教程

[首页](../README.md) · [案例](../examples/single-sale-pet-bed/README.md)

## 1. 安装和调用

按首页方法将本仓库放进 Codex 的 skills 目录，下一轮输入：

~~~text
$temu-es-visual-production
~~~

Agent 应先询问本次商品、SKU、图片存放路径和参考图，同时给出模板与示例，不会凭历史产品开始生图。未显示 Skill 时，可提供安装目录中的 SKILL.md 路径让 Agent 读取执行。

完整图片包需要宿主能读取图片、浏览网页、调用生图和保存文件。本 Skill 不捆绑推理模型、第三方账号或密钥；内置生图可用时直接使用。

## 2. 填写资料并附图

实际生图需要商品名称、清楚外观图、实际售卖配置、SKU 和图片存放父目录。非必要参数可以留空：

~~~text
产品名称：
SKU：本次成品归档使用的SKU；多个SKU请说明各自的图片范围
图片存放路径：如“桌面”、~/Desktop，或完整父目录路径
售卖方式：单件 / 整套出售 / 供货套装拆分单卖
实际到手数量：
尺寸选项：逐个列出；数字含义未知写“不确定”
颜色选项：主推颜色、需要展示的其它可选颜色
商品图片：在消息附图，或提供宿主可读取的图片路径
图片用途：外观 / 氛围 / 版式参考
已确认卖点：
目标人群或使用场景：
视觉偏好和必须保留的细节：
其他要求：是否先提取单品、全新重做、原场景使用次数
输出要求：默认西语图文，1张主图+6张独立详情，全部1:1；先方案后直接制作
~~~

只有“已附图”三个字不算提供图片。有本机路径时，宿主需要能访问该路径。不知道的参数不靠猜测填满。

SKU 和存放位置没有提供时，Agent只补问缺项，收到后再生图；不自动沿用上一款的SKU或桌面/1。多个尺寸共用一套七图时，请指定本批归档SKU或父款编号，不会擅自给每个选项额外生成一整套。

## 3. 写清供货包装和实际销售内容

| 情况 | 应制作的画面 |
|---|---|
| 三件整套卖，到手3个 | 主图清楚展示实际三件，尺寸与每件对应 |
| 两件供货拆成两个尺寸单卖，到手1个 | 主图只展示单件，选购图展示两个可选规格并说明分别出售 |

最新确认的实际售卖方式优先于供货标题。颜色、尺寸属于选择项，不等于一次收到所有选项。

纠正“其实只有两个尺寸”后应按两个执行，不需重填全部资料，也不能沿用旧示例做出第三个。

## 4. 图片分工和单品提取

~~~text
图1锁定外观，图2只参考室内氛围。
先提取两个尺寸的浅灰独立单窝，不叠放、不嵌套。
保留抽条、包边、低开口和棕色小标。
~~~

单品参考是额外资产，不抵扣1张主图和6张详情。遮挡部分只能保守复原，需说明限制，不能当成实拍背面、底部或内部结构证明。

## 5. 审阅逐图方案

每张应包含：买家问题、主要利益、画面证据、镜头/版式、准确西语及中文释义、参考图用途和保真约束。

默认方案后直接生图。只想先审方案时写：

~~~text
这次先只输出调研和逐图方案，等我确认后再生图。
~~~

只需要宣传信息或提示词时也可以说明，Skill会停在文字交付。

## 6. 场景和整套重做

~~~text
覆盖客厅、卧室。不同使用图换狗、换姿势、换镜头。
原参考狗狗场景最多使用一次，其余重新设计。
整套全新生成，保留商品身份，不复用旧成品。
用枕靠动作证明围边，用局部特写展示绒面和抽条。
~~~

重做时新建批次，不把旧图改名或只换标题。系列统一的是配色、字体和光线，画面任务、景别与版式应有变化。

对50×20 cm这样的原始规格，若数字测量口径未知，应明确说明。Agent可保留原文，不应推定直径×高度或画没有依据的高度箭头。

## 7. 自动保存到 SKU 文件夹

例如你填写：

~~~text
SKU：DEMO-PET-BED-GREY
图片存放路径：~/Desktop
~~~

生图并验收通过后，Agent会自动新建以下目录并复制七张成品，你无需再次要求“提取到桌面”：

~~~text
~/Desktop/DEMO-PET-BED-GREY/
  01-main.png
  02-detail-01.png
  03-detail-02.png
  04-detail-03.png
  05-detail-04.png
  06-detail-05.png
  07-detail-06.png
~~~

源文件扩展名会保留。这个文件夹只放七张成品，不混入单窝参考、原图、研究、提示词、总览或ZIP。辅助资料和原始生成母版留在工作批次目录。

已有同名目录时，自动另建 DEMO-PET-BED-GREY-2 等新目录，保留旧图。SKU不能直接用作目录名、路径无法写入或成品不足时，应说明具体问题，不能报告归档完成。用户明确修改成品数量时，以指定数量为准。

实现使用 [归档脚本](../scripts/export_sku_images.py)，仅复制并校验文件，不调用生图API、不修改图片内容。最终回复会给出实际文件夹链接和张数。

## 8. 核对图片包

默认交付：

- 所选父目录下的SKU文件夹：1张主图、6张独立详情，全部1:1。
- 工作目录：按需制作的独立SKU参考与辅助资料，和七张成品分别计数。
- 商品事实、研究记录、西语文案、逐图方案和每张独立Prompt。
- 文件清单、实测像素/大小、目视验收、总览及ZIP。

重点核对外观、数量、规格、小标、宠物姿态、西语和手机可读性。文件检查不替代视觉验收，也不证明销量提升。

无生图能力或部分失败时应分别报告已完成和缺项，不能将提示词包称作完整图片包。

## 常见问题

**为什么还会补问？** 商品图不可读，或最新信息仍有影响外观、售卖内容的核心冲突时需要补问。已明确字段不重复问；非必要参数可以省略。

**只有供应商拼图能做吗？** 可先制作有依据的正面和场景。遮挡结构、纹理放大、小标存在复原限制；关键外观无法核对时需要更清晰素材。

**能直接写机洗、防水、抗焦虑吗？** 必须有本SKU对应证据，不能从竞品或绒面外观推断。案例没有添加这些主张。

**会自动上架吗？** 不会。此Skill交付图片，提交店铺和实拍审核材料属于另一个任务。
